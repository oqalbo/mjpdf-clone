# Committed assets

Everything else in the fixture tree is generated by a script, because a fixture
nobody can regenerate is a fixture nobody can safely change. This directory is
the exception: source material that cannot honestly be produced by a generator,
committed as bytes and copied into `out/` by `generators/assets.py`.

The directory currently contains the permanent TLCL rendering-baseline book
documented below. Other committed assets remain exceptional.

## TLCL 25.12A

- **File:** `TLCL-25.12A.pdf`
- **Version:** 25.12A, Seventh Internet Edition (corrected typos)
- **Title:** *The Linux Command Line Seventh Internet Edition*
- **Author:** William Shotts
- **Source:** <https://sourceforge.net/projects/linuxcommand/files/TLCL/25.12/TLCL-25.12A.pdf/download>
- **Retrieved:** 2026-09-16
- **License:** Creative Commons Attribution-NonCommercial-NoDerivatives 3.0
  United States (CC BY-NC-ND 3.0 US). The file is redistributed unchanged.
- **Size:** 6,519,800 bytes
- **SHA-256:** `c6c564db237ea1d5f5758c5a0df5d8c804041ef483585259687d04d9ecf2cd05`
- **Pages:** 597

`generators/assets.py` refuses to copy this file if either its size or SHA-256
changes. It is committed because the real authored book is the permanent visual
baseline: its typography, tables, figures, code samples and hundreds of pages
are not honestly reproducible with the procedural fixture writer.

## What belongs here

Only files whose value is that they are real.

- **A genuinely scanned document.** This is the one asset really worth
  committing. A scan carries sensor noise, page skew of a degree or two, dust,
  bleed through from the reverse side, uneven illumination and JPEG ringing
  around every letter. `scanned.pdf` and `scanned-long.pdf` are procedural grey
  rasters, which is enough to prove that a page has no text layer and enough to
  size a render budget, but it is not what a photocopier produces. Crop
  detection, image render timing and any golden taken over a scan are all more
  honest against a real one.
- **A real world scientific paper**, for a layout nobody would think to invent:
  two columns, floating figures with captions, tables, footnotes, a reference
  list, an embedded font set from a different toolchain, and a table of contents
  written by a tool that is not this one.

## What does not belong here

- Anything that can be generated. If a script can express it, write the script.
  A committed binary is a diff nobody can review.
- **Anything whose own licence does not permit redistribution.** No
  copyrighted papers, no books, no articles behind a licence, no company
  documents, no material whose terms you have not read. A paper is only usable
  here if its own licence permits redistribution, for example one published
  under a Creative Commons licence, and the licence must be recorded next to it.
- **Personal documents.** No bank statements, no letters, no identity papers, no
  medical records, nothing scanned from anybody's own post. If a real scan is
  needed, scan something written for the purpose, or a public domain page.
- Anything with a person's name, address, signature or photograph in it.

Scan a page you wrote yourself, or a public domain text, on a real scanner. That
gives every artefact worth having and no licensing question at all.

## Naming

**The file name here is the name the test plan uses.** `generators/assets.py`
copies each file into `out/` under exactly the name it carries in this
directory, so `assets/scanned-real.pdf` becomes `out/scanned-real.pdf`. Fixture
names are owned by the test plan: use the name it gives,
and do not coin a second name for something that already has one.

Subdirectories are preserved, so `assets/scan/real.pdf` becomes
`out/scan/real.pdf`, which is how an asset joins a family that lives in a
subdirectory.

`README.md` and dotfiles are skipped and never copied.

## Adding one

1. Confirm the licence, and confirm it is not somebody's private paperwork.
2. Name it what the test plan calls it.
3. Add a line to `REASONS` in `generators/assets.py` saying why it cannot be
   generated. Without one it still gets copied and registered, with a generic
   description that helps nobody.
4. Record the licence and provenance in this file, under a heading of its own.
5. Run `python3 generate.py --only assets --check` and read the manifest entry.

The manifest records the size and SHA-256 of every asset, so a golden recorded
against one stays valid until those bytes change. Assets with a pinned-byte
contract, currently TLCL, additionally fail generation before a changed file can
be copied or registered.
